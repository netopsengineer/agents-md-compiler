# Rendered bundle format version 2

Current public contract. Rendered output and lock serialization are byte-exact.
A change to any byte described here requires a new format value, updated
documentation, explicit golden-diff review, migration and rollback analysis, a
release note, and full integration plus applicable Codex prompt-input
verification. Never regenerate a golden file only to make a test pass.

Format 2 generalizes compiler-owned bytes for global, repository, and nested
`AGENTS.md` targets. It also removes checkout-specific absolute source paths from
the lock. Source requirements and exact source-byte preservation are unchanged.

## Lock file bytes

```json
{
  "bundle_id": "example-project",
  "format_version": 2,
  "manifest_sha256": "MANIFEST_SHA256",
  "modules": [
    {
      "id": "core",
      "source": "modules/core.md",
      "sha256": "MODULE_SHA256",
      "size_bytes": 2561
    }
  ]
}
```

`MANIFEST_SHA256` and `MODULE_SHA256` are metasyntactic tokens in this document
only. Each is a computed lowercase 64-character hexadecimal digest. Never emit a
token literally.

Serialization rules, all mandatory:

- sort object keys lexicographically at every depth;
- use two-space indentation;
- ASCII-escape JSON strings;
- use LF line endings and exactly one final LF;
- preserve manifest order in `modules`;
- set `manifest_sha256` to the digest of the exact manifest bytes;
- set `source` to the exact non-empty lexical source string from the manifest;
- set `size_bytes` to the canonical source's base-10 byte count;
- set `format_version` to the integer `2`.

The lexical `source` value is machine-significant and preserved exactly. It may
be relative, absolute, or tilde-prefixed as permitted by manifest schema 1. The
lock never stores the runtime-resolved source path. Resolution still occurs for
source validation and diagnostics, but moving equal manifest and source bytes to
a different checkout root does not change lock bytes.

The lock never contains source content. `lock` writes the complete lock atomically
or writes nothing.

## Rendered output bytes

```markdown
# Agent Instructions

<!-- agents-md-compiler:generated format=2 -->
<!-- bundle-id: example-project -->
<!-- manifest-sha256: MANIFEST_SHA256 -->
<!-- lock-sha256: LOCK_SHA256 -->
<!-- Do not edit this file. Edit canonical sources and regenerate it. -->

<!-- agents-md-compiler:module-begin id=core sha256=MODULE_SHA256 bytes=SIZE_BYTES -->
# Core Policy

Canonical source bytes continue here.
<!-- agents-md-compiler:module-end id=core -->
```

`MANIFEST_SHA256`, `LOCK_SHA256`, `MODULE_SHA256`, and `SIZE_BYTES` are
metasyntactic tokens in this document only.

### Exact construction

Output is the concatenation of one header block followed by one block per module,
in manifest order. Every line ends with one LF.

Header block, seven lines exactly:

```text
# Agent Instructions
<empty line>
<!-- agents-md-compiler:generated format=2 -->
<!-- bundle-id: {bundle_id} -->
<!-- manifest-sha256: {manifest_sha256} -->
<!-- lock-sha256: {lock_sha256} -->
<!-- Do not edit this file. Edit canonical sources and regenerate it. -->
```

Module block, for each module in order:

```text
<empty line>
<!-- agents-md-compiler:module-begin id={id} sha256={sha256} bytes={size_bytes} -->
{exact canonical source bytes, which already end with exactly one LF}
<!-- agents-md-compiler:module-end id={id} -->
```

Consequences that are part of the contract:

- the first byte is `#` and the last byte is LF;
- exactly one empty line precedes each `module-begin` line;
- no extra empty line is inserted before a `module-end` line;
- nothing follows the final `module-end` line and its LF;
- compiler-owned header and marker bytes are printable ASCII;
- accepted source bytes are preserved exactly.

### Marker grammar

```text
<!-- agents-md-compiler:generated format=2 -->
<!-- agents-md-compiler:module-begin id=IDENT sha256=HEX64 bytes=DIGITS -->
<!-- agents-md-compiler:module-end id=IDENT -->
```

`IDENT` matches `^[a-z][a-z0-9-]{0,63}$`. `HEX64` is 64 lowercase
hexadecimal characters. `DIGITS` is a positive base-10 integer with no sign,
separator, or leading zero. A canonical source containing
`<!-- agents-md-compiler:` is rejected.

## Determinism and self-validation

Given identical manifest bytes, format-2 lock bytes, and source bytes, output
bytes are identical across checkout roots. Output contains no timestamp, host
name, user name, process ID, random value, temporary path, working directory,
resolved source path, or package version.

After rendering, the compiler structurally validates the seven-line header and
each locked module block. It verifies marker identity, exact content length,
content digest, order, module count, and absence of trailing bytes. Target
comparison uses a whole-file digest against that self-validated fresh render.

## Managed-target migration

The current compiler recognizes exact format-1 and format-2 headers in their
documented header positions as managed. It emits only format 2.

| Existing target        | Classification     | Install behavior                       |
|------------------------|--------------------|----------------------------------------|
| Exact current format 2 | `CURRENT`          | No byte replacement is needed          |
| Different format 2     | `DRIFTED`          | Normal explicit install may replace it |
| Format 1               | `DRIFTED`          | Normal explicit install upgrades it    |
| Unknown format value   | `UNMANAGED_TARGET` | Explicit adoption and digest required  |
| No recognized header   | `UNMANAGED_TARGET` | Explicit adoption and digest required  |
| Missing                | `MISSING`          | Normal explicit install may create it  |

An upgrade from format 1 creates an exact backup and receipt before success is
reported. Receipt-based rollback restores the exact format-1 bytes when the
installed format-2 digest still matches.

## Lock migration

The current parser accepts lock formats 1 and 2 strictly. A format-1 lock is
never current against a fresh format-2 lock. Read-only commands report
`LOCK_STALE`; they do not rewrite it. The explicit `lock` command may atomically
replace it after the lock-file concurrency precondition passes.
